# Working on Parchmatte (for people and coding agents)

Parchmatte is a macOS 13+ menu-bar utility that draws click-through paper
textures over the screen or over single windows. One executable target, no
dependencies, using public Apple frameworks (AppKit, CoreGraphics and the
transient QuartzCore/Metal Ribbon renderer). Read this file before changing
anything; `CLAUDE.md` imports it, and other agents should read it directly.

## Non-negotiables

These are product promises made in the README, the privacy policy and the
App Store listing. A change that breaks one is wrong even if it works.

1. **Public APIs only.** No private frameworks, no `SkyLight`, no
   `CGSSpace*`. The typed C wrapper for `CGWindowListCreate` uses its public
   declaration from `CGWindow.h`; Swift does not import its raw-number array.
   Anything else needs the same justification in a comment and a line in
   `docs/APP_STORE.md` 2.5.1.
2. **Never read screen contents, window titles or keystrokes.** The only
   window keys read are `kCGWindowBounds`, `kCGWindowIsOnscreen`,
   `kCGWindowLayer`, `kCGWindowNumber`, `kCGWindowOwnerPID` and
   `kCGWindowOwnerName`. Adding a key means updating `docs/PRIVACY.md`, the
   website's `privacy/index.html`, `docs/SECURITY_PLAN.md` S2 and the S2 grep
   in the same commit.
3. **No input monitoring.** No `CGEventTap`, `NSEvent.addGlobalMonitorForEvents`,
   `addLocalMonitorForEvents`, IOHID or AX calls in `Sources/`. Hotkeys are
   `RegisterEventHotKey` only. (`Tests/Harness/click.swift` posts test clicks;
   that is test code and stays out of `Sources/`.)
4. **No network code.** No `URLSession`, `Network.framework`, sockets or web
   views. The one URL is `AppInfo.privacyPolicyURL`, opened in the browser.
5. **Entitlements are exactly `com.apple.security.app-sandbox`**, both
   builds. Don't add capabilities to `project.yml` or either `.entitlements`.
6. **Opacity never exceeds `AppInfo.maxOpacity` (0.6)**, texture and lamp
   combined. Every path that sets opacity goes through `AppInfo.safeOpacity`
   or `CoverStyle.clamped`.
7. **Covers never take input or focus.** `ignoresMouseEvents = true`,
   `canBecomeKey`/`canBecomeMain` false, no text or images from outside the
   bundle drawn on a cover.
8. **No dependencies.** `Package.swift` has none and the art scripts use
   only the Python standard library. Release tooling (`scripts/asc_api.py`)
   is the one exception and is hash-pinned.

## Build and run (macOS only)

Nothing here builds on Linux; the code imports Cocoa. On a Mac:

```sh
swift build                     # debug binary, uses the "Parchmatte" defaults domain
./scripts/build.sh              # dist/Parchmatte.app, ad-hoc signed, sandboxed
xcodegen generate               # store project, from project.yml
```

The debug binary run from `.build/debug/Parchmatte` writes preferences to
the `Parchmatte` domain, never the user's container. The app bundle uses
the sandbox container for `com.galacticluddite.parchmatte`. Tests rely on
that split; don't merge them. The release GUI harness must snapshot preferences
through the signed app's `--audit-export-preferences` and
`--audit-import-preferences` commands. A shell's `defaults read` can return
an empty domain even when the app has stored settings in its sandbox.

## Animation candidates and owner trials

Read [the animation trial workflow](docs/ANIMATION_TRIALS.md) before changing
minimize/restore motion or preparing a live candidate. An approved demo is the
visual specification: preserve its geometry, rotation, depth, shading and
agreed timing, or document a technical limitation and obtain agreement on the
changed appearance before presenting it as the candidate.

An implementation POC runs through the actual app's rendering, styling,
window identity, stacking and lifecycle. A standalone exploratory probe may
answer a narrow question; it does not prove the shipped behavior. Show and
measure real output; timer callback frequency is not displayed frame rate.

Leave the candidate available for human testing. Restore the protected
production build only after the owner's explicit done/rollback instruction;
fixture closure, automated test completion and timers are not authorization.

## Testing

- **Before every commit:** `swift build` must succeed. If a unit test target
  exists (see audit R5), `swift test` too.
- **Automated test qualification:** hosted CI runs the 92 tests that do not
  require interactive AppKit display integration. The three tests in
  `RibbonDisplayIntegrationTests` exercise compositor callbacks and main-run-loop
  timers and require a logged-in, visible normal desktop. Keep the fixture
  windows visible rather than occluded by another app’s fullscreen Space. Before every release, run unfiltered `swift test`
  in the supported desktop condition and require all 95 tests to pass. A hosted
  CI pass qualifies 92 tests and must not be reported as an all-95 pass.
- **Before a release, on the owner's Mac:** `Tests/Harness/run_audit.sh`
  with the app running. It opens TextEdit windows, switches desktops and
  needs System Events control; it snapshots and restores the user's
  preferences through the signed app, and verifies the restored snapshot.
  A locked console fails the GUI preflight; unlock it before interpreting a
  GUI failure as a product regression. Never run it on a machine you don't
  control and don't run it from CI. Record the result in
  `docs/audit/test-results.md` with the
  commit hash it ran on. `scripts/remote_audit.sh <host>` runs the same
  suites on a second Mac over SSH and copies the results back; that Mac
  needs a display, two desktops, the SSH user at the console, and one
  manual first run from Terminal to accept the permission prompts.
  `--check` is the preflight alone.
- **To request a manual run** on the test Mac, open an issue from the
  "Test request" template with a commit, a flavour and measurable pass
  criteria. Screenshots don't show covers unless Hide from Screenshots is
  off; say so in the evidence.
- **After touching `CoverManager.swift`:** at minimum `scenarios_windows.sh`,
  `scenarios_spaces.sh`, `scenarios_fullscreen.sh` and `scenarios_perf.sh`.
  The perf suite asserts one idle window cover under 2% CPU and a paused app
  under 30 ms CPU per 15 s; keep those passing. For anything touching how
  covers follow windows, also `drag_ab.sh 2 <old.app> <new.app>` with
  `PROBE_FLAGS=--vsync` (real mouse drags, mean/jitter/max gap in px) and
  `drag_cpu.sh <old.app> <new.app>`; `fs_swipe_run.sh` for swipes between a
  full-screen Space and a covered window.
- **After touching `Settings.swift`:** `swift build` then
  `Tests/Harness/fuzz_prefs.sh`. Add any new key to its `keys` array.
- **After touching `HotKeys.swift`:** `swift Tests/Harness/layouts.swift`.
- **After touching textures or `Surfaces.swift`:**
  `swift Tests/Harness/softness_check.swift Sources/Parchmatte/Textures/linen.png`.
- Static checks that run anywhere: `bash -n` on scripts,
  `python3 -m py_compile scripts/*.py Tests/Harness/*.py`, `plutil -lint`
  on every plist and entitlements file, and the S2/S3/S4 greps from
  `docs/SECURITY_PLAN.md` (must return nothing).

## Things that move together

Change one, change all in the same commit:

- A hotkey → `AppController.registerHotKeys()`, the README table, the
  website's hotkey table, `docs/APP_STORE.md` description, `layouts.swift`.
- A texture or lamp name → `Surfaces.swift`, README, website copy,
  `docs/APP_STORE.md` description and keywords, `generate_textures.py`.
- A preference key → `Settings.swift`, `fuzz_prefs.sh` keys, `PRIVACY.md`
  only if it stores something new about the user.
- A window-list key or any new API → rule 2 above, `docs/APP_STORE.md` 2.5.1.
- Version → `project.yml` (`MARKETING_VERSION`, `CURRENT_PROJECT_VERSION`)
  and `Sources/Parchmatte/AppBundleInfo.xml` (both version keys). Commit as
  "Build N".

## App Store metadata rules

Nothing in Apple metadata or in the app may mention GitHub, the free build,
prices elsewhere or "build it yourself" (guidelines 3.1.1 and 2.3.10). That
message lives in the README and on parchmatte.com only. "Open source" as a
plain fact is fine. No health claims in keywords or copy.

## Commits and branches

- Imperative subject under 72 characters, a body that says why. Existing
  history is the style guide.
- Author with a GitHub no-reply address; a personal email in this public
  history is audit finding F4.
- Don't commit `dist/`, `.build/`, `Tests/Harness/bin/`,
  `Tests/Harness/results/`, `docs/store-screenshots/` or
  `Parchmatte.xcodeproj/` (all gitignored). Don't commit anything from an
  experiment tracker; `export_run.sh` reads its settings from the environment.
- Never rewrite history on a shared branch without the owner asking.

## The Galactic Luddite app pattern

Parchmatte is the template for the other apps in this family. A new app
copies the structure rather than the code:

- `Sources/<App>/` with a three-line `main.swift`, one controller, one
  settings wrapper with clamping getters, textures or assets generated by a
  script in `scripts/`.
- `Resources/` with an Info.plist, sandbox-only entitlements for both
  builds, a `PrivacyInfo.xcprivacy` that matches the code.
- `docs/APP_STORE.md`, `PRIVACY.md`, `SECURITY_PLAN.md`, `TEST_PLAN.md`,
  `audit/` with the same section IDs (S1–S8, A–I), and a launch plan.
- `Tests/Harness/` with `lib.sh`, `run_audit.sh` and a `fuzz_prefs.sh`.
- A companion `<app>.com` repo: two static pages, privacy at `/privacy/`,
  no JavaScript, deployed by GitHub Pages from `main`.
- The same promises: public APIs, no network, sandbox only, free source and
  a paid signed build, one privacy policy that the code can be grepped
  against.

This file is the public working contract. Never write private hostnames,
network names, IP addresses or account names into commits, issues or comments;
pass any host through an argument or `PARCHMATTE_HOST`. Never name competitor
apps anywhere in this repo. Humans publish: tagging, merging to the release
branch, store submission and website merges stay with the owner.
